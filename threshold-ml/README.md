# THRESHOLD-ML — audited synthetic pilot

**Status:** corrected Model B research pipeline, not a completed ANC system.
Previous results are invalid and archived, not evidence of attenuation.
See [audit findings and remaining gaps](docs/AUDIT.md) and
[mathematical timing/physical formulation](docs/formulation.md).
No firmware, wiring, UI, or physical deployment work is included.

## What is ready to test on GX10

- Deterministic scene-split simulator with randomized primary/secondary FIRs.
- Two-channel causal input: reference + past estimated disturbance from error audio.
- Compact TCN and GRU future-disturbance predictors.
- Shared bounded path-aware controller and residual/spectral training objective.
- Persistence, sinusoidal regression, FFT, AR and perfect-future-forecast comparisons.
- Separate actual sequential FxLMS baseline (not yet integrated into fair streaming evaluation).
- Checkpoint/resume, CUDA AMP, train-only normalization, scene manifests, JSONL logs.
- Tests and waveform/spectrum/comparison plots generated by evaluation.

Model A is an unvalidated prototype; Model C is explicitly deferred. Do not run the
multitone draft configuration yet. No audited trained v2 checkpoint exists.

## Setup on ASUS Ascent GX10

Use a **Linux ARM64 CUDA PyTorch environment compatible with the GX10 GPU** supplied
or recommended for that machine. Do not assume a generic x86 wheel or CPU PyTorch
installation will provide GPU support. The code detects CUDA/MPS/CPU; GPU commands
below require CUDA deliberately so they cannot silently train on CPU.

Inside an isolated environment with working PyTorch:

```bash
cd threshold-ml
python -c "import torch; print(torch.__version__, torch.version.cuda); assert torch.cuda.is_available(); print(torch.cuda.get_device_name())"
python -m pip install -e '.[dev]'
python -m pytest -q
python scripts/generate_dataset.py --config configs/single_tone.yaml
python scripts/train.py --config configs/single_tone.yaml --device cuda
python scripts/evaluate.py --device cuda \
  --checkpoint artifacts/checkpoints/single_tone_tcn_v2/single_tone_tcn_v2_best.pt \
  --output artifacts/evaluation_tcn_v2
```

GRU comparison: train `configs/single_tone_gru.yaml` separately. Training/evaluation
save complete configuration and normalization in checkpoints; never reconstruct a
model using a different config. Keep checkpoints private/trusted: full resume files
contain Python RNG state and are loaded using `weights_only=False`.

Resume interrupted training (same config, to configured total epochs):

```bash
python scripts/train.py --config configs/single_tone.yaml --device cuda \
  --resume artifacts/checkpoints/single_tone_tcn_v2/single_tone_tcn_v2_last.pt
```

For development checks only, use a virtual environment and `python -m pytest -q`.
Do not override an OS-managed Python environment or run real experiments on the Mac.
Use a new experiment/output directory for each configuration; existing results are
not silently overwritten. Archive `pip freeze`, environment/container version and
GPU driver details on GX10 alongside the automatically logged environment metadata.

## Interpreting results

The score is **d + h_true * bounded_command**, never d minus forecast directly.
Negative attenuation means amplification; per-window failures and percentiles are
saved. The perfect-forecast baseline still has delay, gain, and command constraints.
Initial uncancellable samples are included. This is an isolated cold-start horizon
benchmark; tails beyond the horizon and continuous feedback are not yet evaluated.
All results are simulated, not physical attenuation. Runtime includes separate model
and controller measurements, with accelerator synchronization. No production model
recommendation is justified before corrected experiments and streaming validation.

## Layout

`configs/`, `src/threshold_ml/{simulation,datasets,baselines,models,losses,training,
evaluation,inference}/`, `scripts/`, `tests/`, `artifacts/`, `data/`, `docs/`.

Inference: `threshold_ml.inference.api.ThresholdInferenceAPI` accepts synchronized
reference/error/speaker histories, an estimated FIR and cutoff sample index. It
returns bounded commands and their logical start index. Nonzero-speaker-history
operation is currently out of the training distribution.
